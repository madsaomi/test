# Stanford English Test

Веб-приложение для вступительного тестирования по английскому языку в **Stanford Language Center**.

Студент проходит тест из 50 вопросов (45 с выбором варианта, 5 открытых), результат сохраняется в SQLite и мгновенно отправляется в Telegram администраторам вместе с заполненным бланком ответов.

## Возможности

- 🎯 **Серверная проверка ответов** — вопросы выдаются по одному из серверной сессии, ответы проверяются и хранятся на сервере; клиент не знает правильных ответов и не отправляет их — подделать результат невозможно
- 🎲 **Банк 230 вопросов** (A1–C1) — каждый тест собирается случайно: 50 вопросов по фиксированному плану уровней, перемешанный порядок вопросов и вариантов ответа — у каждого студента свой тест
- ⚡ **Анализ скорости** — сервер замеряет время каждого ответа своими часами; сверхбыстрые ответы и подозрительно короткое прохождение помечаются флагами в Telegram и БД
- ⏱ Таймер на каждый вопрос (30 сек на выбор варианта, 40 сек на ввод формы глагола) — его соблюдает сервер: ответ позже таймера + 5 сек не засчитывается и помечается флагом
- 🛡 Античит: блокировка копирования/скриншотов, контроль ухода со вкладки (3 предупреждения — тест аннулирован)
- 📝 **Генерация официального бланка** (2048×1012) с подсветкой: правильные — зелёным, ошибки — красным с зелёным кольцом на верном варианте, пропуски — жёлтым кольцом
- 📨 Асинхронная отправка в Telegram с ретраями (до 3 попыток; на 429 ждем столько, сколько просит Telegram)
- 🔁 **Повторные сдачи** видны админам: в сообщении «попытка №N с этого номера» и прошлый результат
- 🔁 **Досылка**: если Telegram был недоступен, фоновый цикл раз в 10 минут пересобирает бланк и досылает результат (за последние 7 дней, до 10 попыток)
- 💾 Персистентное хранение результатов и сессий в SQLite (режим WAL)
- 🗄 **Ежедневный бэкап**: после 03:00 по Ташкенту сжатая копия базы приходит админам в Telegram; вручную — `GET /admin/backup`
- 🎨 Фирменный стиль по брендбуку 2021: жёлтый `#FFB703`, чёрный `#070707`, шрифты Source Serif 4 / Montserrat

## Структура проекта

```
app.py               # Flask-приложение: сессионный API, валидация, уровни
database.py          # SQLite: результаты, сессии тестов, миграции
test_session.py      # Банк вопросов, сборка персонального теста, сессии
sheet_generator.py   # Отрисовка бланка ответов (Pillow)
text_utils.py        # Общие функции (нормализация текста для сравнения ответов)
questions.json       # Банк: 200 вопросов с вариантами + 30 открытых (уровни A1-C1)
templates/index.html # Страница теста
static/              # Стили, скрипты, логотипы, фавиконки
```

## API

| Маршрут | Описание |
|---|---|
| `GET /` | Страница теста |
| `POST /test/start` | Создать сессию → `sid` + первый вопрос |
| `POST /api/answer/<sid>` | Ответ `{pos, answer}` → в ответе сразу следующий вопрос |
| `GET /api/question/<sid>` | Текущий вопрос (ресинхронизация) |
| `POST /submit` | `{sid, fio, phone, branch}` — баллы берутся из серверной сессии |
| `GET /admin` | Страница админки (вход по `ADMIN_TOKEN`) |
| `GET /admin/results` | Последние результаты в JSON (требует `ADMIN_TOKEN`) |
| `GET /admin/sheet/<id>` | Бланк ответов результата (требует `ADMIN_TOKEN`) |
| `GET /admin/result/<id>` | Карточка студента (вход в админку) |
| `GET /admin/export.csv` | Выгрузка для Excel; фильтры `period`, `branch`, `flagged` (требует `ADMIN_TOKEN`) |
| `GET /admin/report` | Отчет в Telegram вручную: `?period=ГГГГ-ММ` или `ГГГГ` (требует `ADMIN_TOKEN`) |
| `GET /admin/backup` | Скачать сжатую копию базы (требует `ADMIN_TOKEN`) |

План теста: 45 с выбором (10×A1, 10×A2, 10×B1, 10×B2, 5×C1) + 5 открытых (2×B1, 2×B2, 1×C1).
Брошенные сессии удаляются через 6 часов.

## Запуск локально

```bash
pip install -r requirements.txt

python app.py          # http://127.0.0.1:5000
```

## Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота из @BotFather |
| `CHAT_ID` | ID получателей через запятую (личные или групповые со знаком `-`) |
| `ADMIN_TOKEN` | Токен админ-эндпоинта; если пусто — эндпоинт выключен |
| `DATABASE_PATH` | Путь к SQLite-базе (по умолчанию `results.db`) |
| `PORT` | Порт сервера (по умолчанию 5000) |
| `BACKUP_ENABLED` | Ежедневный бэкап базы в Telegram (`1` по умолчанию, `0` — выключить) |
| `BACKUP_HOUR` | Час по Ташкенту, после которого отправляется бэкап (по умолчанию `3`) |
| `TRUSTED_PROXIES` | Сколько прокси перед приложением дописывают `X-Forwarded-For` (Railway/Heroku — `1`, по умолчанию; без прокси — `0`) |

Сгенерировать `ADMIN_TOKEN`: `python -c "import secrets; print(secrets.token_hex(32))"`

## Админка

Откройте **`/admin`** в браузере и введите `ADMIN_TOKEN`. Вход сохраняется на 12 часов (cookie с подписью токена, не сам токен; HttpOnly, SameSite=Strict).

На странице:
- фильтры: период (сегодня / 7 дней / месяц / все время), филиал, «только подозрительные»;
- сводка за выбранный период: сколько сдали, средний балл, подозрительные, распределение по уровням;
- список сдавших: имя, телефон (нажать — позвонить), балл и уровень, проверка честности простыми словами
  («2 ответа пришли после таймера — не засчитаны»), номер попытки, статус Telegram; поиск по имени, телефону, школе;
- карточка студента («Подробнее»): контакты, все попытки с номера, причины подозрений, бланк ответов;
- выгрузка в Excel (CSV с текущими фильтрами), скачивание бэкапа, отправка отчета в Telegram.
На телефоне список показывается карточками.

Если `ADMIN_TOKEN` не задан, админка выключена (404). После 10 неверных токенов с IP за 15 минут вход блокируется.

Для скриптов те же данные доступны в JSON: `GET /admin/results?limit=100` с заголовком `X-Admin-Token: <ADMIN_TOKEN>` (или `?key=`).

## Бэкап и восстановление

Каждый день админам приходит файл `stanford-results-ГГГГ-ММ-ДД.db.gz` (результаты и маркеры отчетов; незавершенные сессии не входят).
Скачать копию в любой момент: `GET /admin/backup` с `X-Admin-Token`.

Восстановление: распаковать `.gz` и положить файл по пути `DATABASE_PATH` (на Railway — `/data/results.db`), затем перезапустить сервис.

⚠️ В файле ФИО и телефоны студентов — храните чат админов закрытым.

## Деплой на Railway

1. **Volume (обязательно!)** — файловая система Railway эфемерна: без постоянного диска `results.db` стирается при каждом деплое. Service → **Volumes** → mount path `/data`, затем переменная `DATABASE_PATH=/data/results.db`
2. **Variables**: `BOT_TOKEN`, `CHAT_ID`, `ADMIN_TOKEN` (опционально)
3. Deploy from repo — Dockerfile подхватится автоматически (шрифты DejaVu + tzdata уже внутри, время — по Ташкенту)

**Heroku** — используется `Procfile` (gunicorn); для Heroku Postgres не настроено, база — файл SQLite.

## Лимиты (анти-спам, с расчетом на класс за одним Wi-Fi)

- 60 стартов теста с IP за 10 минут
- 30 успешных отправок с IP за 10 минут

Счетчики хранятся в SQLite и общие для всех gunicorn-воркеров. IP клиента берется из доверенной записи `X-Forwarded-For` (см. `TRUSTED_PROXIES`) — подделать его заголовком нельзя.

## Безопасность

- Валидация всех входных данных: ФИО ≥ 3 символов, телефон строго `+998XXXXXXXXX`, ответы — только короткие строки
- Сессионная схема: вопросы по одному, баллы и правильность — только на сервере, повторная отправка сессии невозможна
- Rate limit по IP (см. «Лимиты»), общий для всех воркеров
- Флаги скорости: сверхбыстрые ответы, ответы после таймера и прохождение быстрее 6 минут помечаются в Telegram
- Honeypot-поле против ботов
- HTML-экранирование пользовательских данных в сообщениях Telegram
- JSON-ответы для ошибок API (400/404/405/429/500); человеку в браузере — страница «Не найдено»
- Заголовки безопасности: CSP (скрипты только свои и jsdelivr, запрет встраивания во фрейм), X-Frame-Options, nosniff, HSTS, Referrer-Policy
- Админ-эндпоинты: 10 неверных токенов с IP за 15 минут — блокировка (429)
- Секреты только через переменные окружения; `.env` исключён из git и Docker-образа

Один тест — 50 вопросов. Результат: балл из 50 и уровень от Beginner до Upper-Intermediate+ (пороги: 15 / 24 / 32 / 39 / 45).
